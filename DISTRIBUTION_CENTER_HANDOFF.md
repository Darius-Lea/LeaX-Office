## Architecture and continuation

- `public/office.js` lazily selects `public/distribution-scene.js` for durable office ID `sales`; `public/office3d.js` owns Headquarters/Marketing and the connected meeting room. Do not rename the saved ID or recreate existing records.
- `src/distribution.ts` projects existing commerce/store/business/operations state without advancing work. `src/server.ts` exposes authenticated proof images/HTML, job-preparation HTML and distribution state. Proofs require the current positive revision and verified byte digest.
- `public/distribution.js` opens exact file/worker/station inspections and reuses existing manual deal/work-order APIs. Request IDs and recovery prevent a lost successful response from duplicating the job.
- `public/distribution.css` styles the records/proofs; renderer surfaces and camera/touch behavior are in `public/style.css`. Keep CSP strict and new styles static.
- `scripts/qa/distribution-browser-check.mjs` runs source or standalone production via HQ_TEST_PACKAGED, uses synthetic isolated data, tests actual pixels, saved files, desktop/touch and unchanged-poll resource stability. Follow scripts/qa/README.md.
- `design/Distribution Center.reference.html` is the original user design reference, excluded from production. Do not serve its default demonstration data or remote CDN script.

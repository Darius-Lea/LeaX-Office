# Native Windows setup

`main_windows.go` is an unsigned native x64 GUI, cross-built with Go. `database-restore.mjs` validates and copies SQLite backups using the verified Node runtime. `scripts/build-native-installer.py` builds the Common Controls resource and embeds an allowlisted application snapshot; generated payload/resource files are ignored. The committed executable is in `downloads/` with SHA-256 sidecar.

This is not code signed and has not been executed on Windows in this Linux workspace. Hidden child processes do not change Windows execution policy. Runtime downloads require official HTTPS checksums plus successful Windows Authenticode verification. Private Ollama and a hardware-selected free model now install/configure automatically; no paid service, external sender or OS startup task is enabled. Existing data stays outside application versions. Backup import requires explicit replacement confirmation, a stopped office, schema/integrity checks and a recovery/archive path.

The native window starts setup automatically on opening. `ai_policy.go` holds pinned official runtime digest, memory/model policy and bounded disk-streaming archive extraction. `local_ai_windows.go` manages the private runtime/process/download/pull; `scripts/configure-local-ai.mjs` requires a completed genuine local inference before saving the connection. Official release checksum source: https://github.com/ollama/ollama/releases/tag/v0.40.7 (asset digest and sha256sum.txt, checked 2026-10-21).


2026-10-21 reliability audit: The production payload contains a bundled/minified runtime, assets, required setup helper and file-integrity manifest. Native setup verifies the manifest and no longer runs npm on a customer device. It starts `runtime/server.mjs`. This reduces installed development clutter; it does not make client-side code impossible to inspect or reverse-engineer.

Opening a healthy current office reuses its running owned engine and opens immediately. Updates prepare verified application/runtime/model downloads before replacing the existing owned server, reducing avoidable downtime on network failures. Copied launchers are identified by executable SHA-256, so a native-only update cannot leave the desktop shortcut pointing at stale setup code.

Setup has a visible progress indicator and **Cancel setup**. Closing during setup cancels network requests, foreground helpers, bounded hashing/extraction and waiting; newly started owned processes are stopped on cancellation. Business databases, completed models and prior app versions remain. Import only changes database files after validation/recovery preparation; cancellation does not interrupt the short archive/install rename sequence. Optional SAM access is collapsed by default. No Windows installation, GUI cancellation, DPAPI, signature or shortcut execution has been validated in this Linux workspace.

# Run and recover
From repository root with Node 24.19+ within 24.x: npm ci --ignore-scripts; npm test; npm start. The normal server includes its own bounded office loop; use npm run worker only as an alternative standalone processing mode. Cloud environments do not need additional worktrees. Future tasks must restart processes; snapshots do not preserve them.
The app is loopback only, HTTP for local use. Do not bind publicly or use it as a production SaaS deployment. PORT defaults to 4310. HQ_DATA_DIR defaults to data/ under working directory. Keep startup working directory consistent.

Stop worker/server before manual restore. Preserve original data directory. Copy a verified backup to a new private directory as headquarters.sqlite, then start with HQ_DATA_DIR pointing there. Do not combine a restored database with old -wal/-shm files. Run PRAGMA integrity_check and inspect tasks before restarting worker. Lease recovery can take 60 seconds. Backup restore is exercised in npm test. Backup contains password hashes and business data; protect it. UI backups are not an off-device disaster recovery strategy.

Windows: install Node 24.19+, run commands from project root. Optional scripts/windows-worker.ps1 registers a worker at sign-in only when manually executed. Stop and disable via Stop-ScheduledTask AIHeadquartersWorker and Disable-ScheduledTask AIHeadquartersWorker. Remove via Unregister-ScheduledTask when appropriate. Windows behavior remains unverified.

## Render port-binding fix (2026-10-21)
Use Node 24.19.x (package engines now constrain the runtime to 24.x).
In Render service settings use build command `npm ci --ignore-scripts` and start command `npm start`. Do not mix Yarn with the committed npm lockfile.
Render's `RENDER=true` now selects `0.0.0.0` automatically and the server respects its `PORT`. Outside Render, set `HOST=0.0.0.0` explicitly for public binding. Local default stays 127.0.0.1.

Public startup requires an HTTPS app origin: Render supplies RENDER_EXTERNAL_URL, or set PUBLIC_ORIGIN to your exact app origin, e.g. https://your-service.onrender.com. A custom domain needs PUBLIC_ORIGIN set to that domain. Paths, credentials, query strings and fragments are rejected. Requests do not choose their own trusted origin using Host or forwarded headers. Configure health check path `/api/status`.

Before first public startup, create HQ_SETUP_CODE as a private Render environment variable containing a newly generated random value of at least 32 characters. Do not reuse the code exposed in previous deployment logs or paste the new value in chat. Public startup will fail with a clear error until this is configured; it never logs the code. In the founder setup screen enter that code and choose your password. Existing founder records are not replaced. You can remove the variable after setup if the database persists. Public HTTPS sessions use Secure cookies. TLS must terminate at Render's proxy; this server remains HTTP internally.

CRITICAL: the free Render web-service filesystem is ephemeral. SQLite data, founder credentials, task history and local backups can disappear on redeploy/restart. Do not treat a free Render instance as durable storage for business data. If you separately authorize a durable disk, mount it and set HQ_DATA_DIR to an absolute folder on that disk; disks may require a paid Render plan. No paid resource is provisioned by this code. Otherwise keep the durable application on your Windows computer until a free durable storage adapter exists. Cloud account storage is separate from your Windows database; credentials/data are not synchronized automatically. The web service includes the office processing loop, gated by saved clock state; a separate worker is unnecessary for normal use.

This patch enables network binding and HTTPS-origin authentication only; it is not a security audit, tenant-isolation implementation or production-readiness claim. Remote Ollama and persistent cloud worker deployment remain unfinished. No live Render deployment was performed from this workspace.

# Architecture
Node 24 native TypeScript stripping, built-in HTTP server and SQLite; static HTML/CSS/JavaScript dashboard. No build step. Prepared SQL statements; persistent tasks, evidence checkpoints, audit records, founder hash and expiring sessions. Scrypt password hashing and random one-time console bootstrap. HttpOnly SameSite cookie, origin checks, login throttling, loopback binding and restrictive CSP. This is a single-founder local app, not a multi-tenant SaaS security boundary.

Alpha checks a fixed USAspending public source. It records provenance rather than interpreting portal availability as a business lead. Bravo reviews source provenance and marks missing extraction as blocked. SQLite immediate transactions serialize job claims; 60-second leases recover interrupted claims. Only read-only remote work is implemented; no consequential external actions or inferred approvals.

## Contract-award research milestone
research.ts defines fixed source metadata, bounded requests and response validation. Alpha processes one API page per claim, atomically persisting award records, task_findings associations and the next-page checkpoint. Opportunities retain their existing table and URLs deduplicate across assignments; joins preserve each task's evidence association. Bravo reviews provenance, flags records as reviewed and completes the bounded research task; it never claims contact or business qualification verification. Missing source access blocks the task. Retry requeues only Blocked tasks with attempts reset and checkpoints retained. Additive CREATE TABLE migration preserves founder, sessions and prior data. Exhausted abandoned leases transition to Blocked instead of remaining Running forever.

Office orchestration: office.ts gates a non-overlapping web-process pulse with persisted clock state, resets to out at web-process startup, and queues the standing goal on clock-in when no queued/running task exists. After six hours idle, it queues another bounded research cycle while clocked in. Worker tick still owns transactional claims/checkpoints. New employees and review_notes tables are additive. Custom roster configurations do not grant executable capabilities. Company profile and goal use settings. Original research evidence is immutable through owner-annotation APIs. Initial CSS 3D room uses task states rather than simulated work; all views use one dataset.

team.ts adds additive idempotent team_jobs, office_notes and prospects. A completed task seeds one job per internal role atomically; each pulse commits one deterministic role output and audit. Unique(task,agent) prevents duplicate note delivery after replay. No external communications or contact guesses. Owner notes/read flags are authenticated. A browser-open endpoint resumes office authorization except after explicit manual pause; importing office.ts no longer resets persisted clock. Office view remains CSS 3D; notes and file controls share the same records.

manager.ts owns a persisted throttled supervision pass in the authorized office pulse before worker claims. It transactionally reconciles abandoned leases/follow-up reports, records issues and the next visited employee, and deduplicates attention notes with stable issue signatures. No network retry or consequential external action is issued. managerState and ROLE_CHARTERS are authenticated state fields. The manager figure uses the recorded visitedAgent and is hidden when clocked out; employee desk nodes remain stable between polls for actual target transitions. Store migration changes only original Hotel name/role defaults while keeping internal IDs. background.ts provides the complete office loop for npm worker/Windows opt-in use.

# Security boundaries

## Preview.9 meeting, media and visitor boundaries

Invitation codes and partner session tokens are hashed; one-use expiring invitations create scoped meeting accounts, never founder access. All mutation routes require an exact trusted Origin; private owner routes require the independent founder cookie. Revocation is checked on each request. Shared meeting views omit owner-only docket/profile/tool/private records. Human chat requires actual meeting invitation and recent joined presence. Camera/microphone/STUN access is a separate explicit consent; no recording is implemented. Signaling is recipient-scoped, bounded and short-lived. Remote peer IP disclosure is explained; no TURN service is bundled.

Support requests are unauthenticated plain-text submissions with persisted pacing; no file upload or preview is accepted. Payment links are restricted to supported official provider URLs; no transaction token/bank connection or verification is present. Visitor links remain plain text in owner views. Owner/AI text-risk review is not antivirus or malware scanning. Payment approval grants neither membership nor booking. Keep real payments and files at trusted providers.

Teaching fetches use existing public DNS/HTTPS/robots safeguards, no redirects, a 128 KB/30-row direct JSONL limit and explicit permission/review attestation. No dataset code executes, no preview becomes an automatic model instruction, and no examples enter shared generic-learning exports. Source licensing is owner attestation, not independently certified. Bitcoin monitoring accepts a public validated mainnet address only and reads fixed public mempool.space endpoints after consent; no private keys/spending/mining permissions exist.
Single-founder local prototype. Console possession plus first-run code is required to establish founder access; email alone grants nothing. Passwords are scrypt hashes with random salts. Sessions expire after eight hours. Authentication APIs throttle repeated requests. State-changing requests require matching local Origin; session cookies are HttpOnly/SameSite Strict. No external writes or arbitrary URL tools. Model and research outputs cannot grant permissions.
No secrets in frontend or Git. Data and backups contain sensitive records; filesystem/user-account protection and encrypted disks are recommended. Not hardened or audited for public hosting. No tenant isolation or remote deployment authorization implied. Security reporting: open a private maintainer channel; do not post credentials.

Public binding is now an explicit deployment mode (automatic on Render). It requires a configured HTTPS origin and private first-run HQ_SETUP_CODE, never prints public bootstrap codes, and issues Secure cookies. Origin validation does not trust forwarded headers. The code previously printed in deployment logs must not be reused. These controls do not establish public production readiness; tenant isolation/security auditing remain outstanding.

## Local AI, contact reader and transfers
Ollama connects to fixed loopback tags/chat/pull endpoints, with bounded context/output and no model-executable browser/email/filesystem tools. Untrusted web evidence cannot grant permissions. Generated advice is not verification. Cycle context is explicitly linked; interrupted inference is blocked rather than invented. Owner-authorized native setup prepares its private starter model automatically; advanced model pulls require the existing confirmation gate. Hosted requests cannot trigger native starter-model installation.

Public contact reading rejects private/reserved destinations and credential query fields, pins validated DNS to avoid rebind, preserves TLS verification, honors applicable crawler robots groups and caps same-origin redirects/time/body/concurrency. It is an owner-supplied public-page reader, not a bypass for private search systems. Published contacts have explicit unverified identity/deliverability/permission status.

Draft preparation validates recipients against saved published contacts, or fresh current-notice POCs. Subject/header injection is rejected; edits reset approval. Only an owner-approved draft can create a mailto composer link. There is no sending/bidding tool or model authorization path. The owner's mail application retains final sending control.

SAM keys are accepted only through authenticated, exact-origin state-changing requests. Installed Windows uses a private stdin pipe to its user-DPAPI helper; no key enters command arguments. Hosted/non-native offices use AES-256-GCM with a random private master key in the retained office data folder, then restore the saved credential into process memory on startup. Those files require host/user filesystem protection; encryption does not protect against a compromised host or account with access to both files. Credentials stay outside SQLite, backups, state responses and shared downloads. Free Render resets can lose saved credentials alongside other local files. API request URLs/exception bodies containing keys are never persisted. Public source evidence is separate from generated notes. No raw process environment or credential files are printed.

Local first-run bootstrap uses a private fragment on loopback, consumed and erased in browser history; fragments are not sent in HTTP requests. Injected bootstrap values are suppressed from logs. Database export requires authentication and includes sensitive business records, password hashes and sessions; keep downloads private. Import requires explicit stopped-office confirmation and preserves verified recovery files. These controls do not establish audited multi-tenant/public SaaS security.


Focused advice uses text content rather than executable source markup. Read-aloud is user initiated and selects installed English voices only; it does not send note text to a cloud speech API. Office-design updates are authenticated, origin checked, limited to known enum/boolean fields and stored separately from immutable source evidence. A visual change grants no new employee tools or external-action permissions.


Preview.4 contact enrichment uses a fixed public search origin, actual candidate/linked URLs only, exact company-source boundaries, public-IP/TLS pinning and robots checks. Candidate contacts cannot supply a draft ID until company-site identity is owner-confirmed and the page is stored through the contact reader. Confirmation is an owner attestation, not independent corporate verification. No guessed domains, login automation or external sending is enabled. Source quotes use text rendering/escaped print output. Jobs keep prior observations in history on refresh; same-company dated reuse retains its original timestamp. All lead/print/research routes require the founder session, with exact-origin protection for mutations.

## Automatic planning and feedback — preview.5

Live operations is a read-only projection of saved state; viewing it does not enqueue jobs or train the priority model. Learning state requires founder authentication. Reward/correction writes additionally require the matching Origin, an eligible actual receipt, employee ownership and valid feedback. Queued/blocked/setup states and source outages cannot be rewarded as completed work or penalized as misconduct. Feedback is deduplicated per saved receipt/employee/source and original evidence remains unchanged.

Local Bayesian priority learning cannot add tools, remove approvals, alter source URLs, bypass site confirmation, change retry/budget limits or override clock-out. Automatic planning selects only permitted work, uses bounded source backoff and tracks actual contact starts. Draft creation rechecks the exact company's completed published contact receipt; stale/unusable sources produce a saved hold. Corrections can arrange recovery or a bounded genuine model review, not arbitrary filesystem/browser/email execution. Excused incident feedback is excluded from active training while history is retained. No external learning service, account, payment or Windows startup registration is introduced.


## Opportunity records, backups and history — preview.6

Opportunity reads require founder authentication; creation, edits, outcomes and manual backup requests additionally require the matching Origin. Source kind/company and result-derived stages cannot be overwritten through case edits. Revision checks reject stale saves. Saved award identity is matched to its recipient and source URL; notices retain current deadline/freshness classification. Company contacts require matching published-source receipts. Ambiguous jobs do not inherit company-level drafts or worksheets as though those records belonged to a specific scope.

Reported case results link to the existing outcome ledger rather than duplicating money. Correction/void history is retained, and changing an outcome to another company removes its attribution to the old case. These owner reports do not verify customer intent, bank receipts or accounting profit. No sending, submission or arbitrary computer-control permission is introduced.

Managed backup copies are consistent SQLite snapshots verified for integrity/schema and hashed before publication. The managed directory/files use private permissions; retention only removes catalog-owned unchanged backup files after a new verified copy exists, preserving manual/foreign/changed files. Backups contain sensitive founder/session/business records; service keys remain outside SQLite. Same-host storage and encryption do not protect against a compromised account or lost host. Authenticated export uses isolated private staging, streams a verified standalone copy and cleans only that request's files after success/failure/disconnect.

History pagination validates bounds and uses literal parameterized search; it does not delete older records. Approval and composer checks reject unfinished owner placeholders, including legacy approved drafts. Native AI reuse requires the exact selected installed model and prior completed-inference proof; the loopback readiness response exposes only the nonsecret model identifier needed for that check. Model context remains bounded and untrusted case text cannot authorize tools or external actions.
